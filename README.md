# RRC — RangS Reusable Components

RRC is a collection of reusable components and starter templates for web, desktop, game development, scripting, and system projects. Browse the templates, choose one that fits your needs, and adapt it for your project.

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

## Explore the templates

| Category | What's inside |
| --- | --- |
| [CLI](templates/cli/) | Command-line application templates |
| [Desktop](templates/desktop/) | Desktop application templates |
| [Game development](templates/gamedev/) | Templates organized by engine, including Godot and LÖVE2D |
| [Scripts](templates/script/) | Standalone scripts and project configuration |
| [Static websites](templates/static/) | Blog, documentation, and landing page templates |
| [System](templates/system/) | Operating system and package templates |
| [Web](templates/web/) | Front-end, back-end, and full-stack templates |

For example, the [React template](templates/web/front-end/react/) includes reusable components such as a header, navigation, cards, articles, and a footer. See its [usage guide](templates/web/front-end/react/README.md) for setup and examples.

## Get started

Clone the repository:

```bash
git clone https://github.com/RangS-1/RRC.git
cd RRC
```

Browse the category folders, then copy the template you want into your project. Before using it, read any README or setup instructions included with that template; dependencies and setup steps may differ between templates.

## Contribute

Contributions are welcome, whether you're adding a template, improving an existing one, or fixing documentation. To get started:

1. Fork this repository and clone your fork.
2. Add or update a template in the appropriate category under `templates/`.
3. Follow the naming and structure requirements in [RULES.md](RULES.md).
4. Test your changes and update the template's documentation where needed.
5. Open a pull request describing the change. Include screenshots for visual templates when applicable.

Read the full [contribution guide](CONTRIBUTING.md) before opening a pull request. A focused change with clear setup instructions makes review easier for everyone.
